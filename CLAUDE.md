# CLAUDE.md

Гид для Claude Code по проекту **friendly-app-builder**. Главная задача этого
файла — зафиксировать идею приложения и его **визуальный дизайн**, чтобы при
любой работе внешний вид, оформление и стилистика оставались ровно такими, как
сейчас. Меняем поведение и данные — **не меняем внешний вид**.

---

## 1. Что это за приложение

**«Трекер развивающих занятий»** — мягкое ежедневное сопровождение развития
ребёнка. Это mobile-first одностраничное приложение-чеклист: родитель отмечает
выполненные занятия, видит прогресс дня и красивую статистику.

Три экрана (нижняя навигация из 3 вкладок):

- **Сегодня** (`/`) — прогресс дня (кольцо), кнопка «Предложить следующее
  занятие», занятия, сгруппированные в блоки-категории, каждое — карточкой с
  чекбоксом.
- **Статистика** (`/stats`) — серии, активные дни, столбики за 14 дней, тепловая
  карта, полоски «что проседает».
- **Ещё** (`/more`) — настройки: напоминания, облако, бэкап, тема, сброс.

Язык интерфейса — **русский (`ru-RU`)**. Тон — тёплый, поддерживающий.

---

## 2. Стек и структура

- **Vite 8** + **React 19** + **TypeScript**
- **TanStack Start / Router** — файловый роутинг в `src/routes/*`
  (`routeTree.gen.ts` генерируется автоматически — **не редактировать руками**)
- **Tailwind CSS v4** (конфигурация через `@theme` прямо в `src/styles.css`)
- **shadcn/ui** (Radix) — готовые компоненты в `src/components/ui/*`
- **framer-motion** — анимации, **lucide-react** — иконки, **recharts** — графики
- Пакетный менеджер — **bun**

Ключевые каталоги:

```
src/
  routes/            экраны (index, stats, more, __root)
  components/        GameCard, CategoryBlock, ProgressCircle, NavigationBar,
                     StatisticsCard, HeatMap, GradientBlobs
  components/ui/     shadcn-компоненты (button, drawer, sheet, dialog, ...)
  lib/data/          DataService.ts — единая точка доступа к данным
                     types.ts — модели (Game, Category, ...)
                     mock.ts  — сид-данные
  styles.css         дизайн-токены и утилиты (ИСТОЧНИК ИСТИНЫ по дизайну)
```

### Данные идут только через DataService

`src/lib/data/DataService.ts` — **единственная** точка доступа к данным. Сейчас
он на мок-данных (`mock.ts`) + `localStorage` для статусов, и специально сделан
так, чтобы позже переключиться на Supabase **без изменений в UI**. Любые новые
данные добавляются через `types.ts` + `mock.ts` + методы `DataService`, а не
хардкодом в компонентах.

## 3. ДИЗАЙН — НЕ МЕНЯТЬ

Это ядро файла. Всё ниже — **инвариант**. Новый функционал обязан использовать
**существующие токены и компоненты**, чтобы визуально ничего не поехало.

### 3.1. Токены (единственный источник — `src/styles.css`)

- **Радиус:** база `--radius: 1.25rem`; карточки — `rounded-3xl`, крупные блоки —
  `rounded-3xl`/`rounded-b-[2.5rem]`, чипы — `rounded-2xl`/`rounded-full`.
- **Основной градиент:** `--gradient-primary`
  = `linear-gradient(135deg, oklch(0.62 0.22 264), oklch(0.45 0.25 285) 55%, oklch(0.5 0.27 305))`
  (сине-фиолетовый). Используется через утилиты `bg-gradient-primary` и
  `text-gradient-primary`.
- **Тени:** `shadow-card` (мягкая тень карточек), `shadow-soft`, `shadow-glow`
  (свечение под градиентными элементами). Только эти три.
- **Поверхности:** `bg-surface` (белый), `bg-surface-2` (светло-сиреневый фон
  чипов/строк), `bg-background` (общий фон страницы).
- **Текст:** `text-foreground`, `text-muted-foreground`; акцентный заголовок —
  `text-gradient-primary`.
- **Шрифт:** **Manrope** (веса 400–800), подключается в `__root.tsx`.
- **Цветовая система — только OKLCH.** Не вводить hex/rgb, не добавлять новые
  цвета мимо токенов.

### 3.2. Компоненты-паттерны (переиспользовать, не переизобретать)

- **Карточка** = `rounded-3xl bg-surface p-4 shadow-card ring-1 ring-black/[0.04]`.
- **Заголовок-хедер экрана** = градиентный блок сверху со скруглением снизу
  (`rounded-b-[2.5rem]`), фоновыми блобами `<GradientBlobs />`, крупным
  `text-3xl font-extrabold` заголовком и подписью `text-sm text-muted-foreground`.
- **Первичная кнопка** = `rounded-full bg-gradient-primary text-white shadow-glow`.
- **Вторичная кнопка** = `rounded-full border-2 border-[oklch(0.62_0.22_264)]
text-[oklch(0.45_0.25_285)]`.
- **Иконка-«плитка»** = `grid place-items-center rounded-xl bg-gradient-primary
text-white shadow-soft`.
- **Нижняя навигация** — стеклянная плашка `bg-white/80 backdrop-blur-xl`,
  активная вкладка подсвечивается `bg-gradient-primary`.
- Списки появляются со `stagger`-анимацией через framer-motion; чекбокс
  анимируется пружиной. Эти анимации сохраняем.

### 3.3. Раскладка

- Всё приложение центрировано и ограничено по ширине: `mx-auto max-w-md`
  (мобильный контейнер). Любой новый экран/оверлей держим в этих же рамках.
- Нижняя навигация фиксирована; у контента отступ снизу `pb-28`.

### 3.4. Что делать нельзя (визуальные красные линии)

- ❌ Менять `styles.css`: токены, `--radius`, градиент, тени, шрифт, палитру.
- ❌ Менять визуальные классы существующих компонентов (`GameCard`,
  `CategoryBlock`, `ProgressCircle`, `NavigationBar`, хедеры экранов): цвета,
  скругления, тени, отступы, типографику, анимации.
- ❌ Вводить сторонние UI-киты, новые шрифты, тёмные/цветные темы, эмодзи-стиль,
  отличный от текущего.
- ❌ Ломать mobile-first `max-w-md`-раскладку.
- ❌ Подключать сторонние стили/CSS-фреймворки помимо Tailwind-токенов проекта.

### 3.5. Что делать можно

- ✅ Добавлять данные и поля моделей (через `types.ts`/`mock.ts`/`DataService`).
- ✅ Добавлять новый функционал и даже новые экраны/оверлеи — **при условии**,
  что они собраны из существующих токенов и компонентов `components/ui/*`
  (Drawer, Sheet, Dialog, Badge и т.д.) и выглядят как родные.
- ✅ Оживлять уже существующие, но «пустые» контролы (например, кнопка ▶ на
  карточке сейчас ничего не делает — ей можно дать поведение, не меняя вид).
- ✅ Позже заменить мок-слой на Supabase внутри `DataService` без правок UI.

Правило проверки: **после изменений скриншот экрана должен быть визуально
неотличим от прежнего** (кроме нового содержимого/оверлеев, собранных из тех же
токенов).
